## 0. 前提認識

**本プロジェクトは土木・建設業務アプリケーションではなく、AIコーディングツール（Claude Code / Codex）の起動・設定・プロンプト・テンプレートを一元管理する「開発者ツールキット」である。**

したがって、評価フレームワークの一部（業務適合性の現場利用、工事管理機能など）は直接適用できない。本評価では、土木建設会社のIT/DX部門（7名）が本ツールキットを**開発インフラとして本番導入する際の適合性**を評価する。

## 3. 総合判定

**条件付き利用可** → 重大バグ修正後は **本番利用可（IT/DX部門の開発インフラとして）**

クリティカルバグ（launch.sh readonly TOOLKIT_ROOT回帰）を修正したv0.3.1-devでは、開発インフラとしての本番利用が可能。ただし以下の条件を推奨：

1. `AI_WEBUI_TOKEN` を必ず設定する（fail-open問題の緩和）
2. LAN公開時は `AI_WEBUI_HOST=0.0.0.0` + トークン必須を強制するコード改修を実施
3. Codex YOLOモードのリスクを受容するか、`AI_WEBUI_ALLOW_DANGEROUS` フラグを追加
4. symlink経由のルート検証バイパス対策を実装
5. 定期的なE2Eテスト（実CLI環境での検証）を運用フローに組み込む

## 4. 強み・弱み

### 強み（上位15件）

1. **CI/CDの充実**: ShellCheck/PSScriptAnalyzer/Bats/Pester/Nodeの5系統をマルチOSで自動実行。セキュリティスキャン・依存関係監査も週次自動化
2. **セキュリティ設計の網羅性**: 脅威モデル・制御・禁止実装が設計書に明記。CSP・レート制限・タイミングセーフ認証・systemd sandbox
3. **監査ログの実装**: JSONL形式・日次ローテーション・gzip圧縮・秘密値マスキング・7世代保持 — エンタープライズ要件を満たす
4. **日本語での完全文書化**: 要件定義書375行・設計書752行・Runbook・導入ガイド・ADR。7人チームでの引き継ぎに最適
5. **WebUI**: 依存ゼロのバニラJS SPA。xterm.js同梱。PTY中継。死活監視。全操作をブラウザ完結
6. **dry-run既定**: 全操作がプレビューから始まる設計。安全ポリシーに完全準拠
7. **冪等性・ロールバック**: 再実行での重複変更なし。バックアップからの復元手順完備
8. **7統合元リポジトリの移行完了**: 全資産に出典・SHA・判定が記録され追跡可能
9. **依存ゼロのWebUIサーバー**: Node.js標準モジュールのみ。追加パッケージ不要
10. **systemd hardening**: NoNewPrivileges, ProtectSystem=strict, PrivateTmp, ReadOnlyPaths
11. **テストカバレッジ**: 75テスト、全合格。API・WebSocket・PTY・パス検証・セッション管理をカバー
12. **CHANGELOGの品質**: Added/Changed/Fixed/Security分類、バージョン間差分が明確
13. **クロスプラットフォーム**: Linux/Windowsで同等機能。SSH経由のWindows操作
14. **バージョン単一正本化**: `package.json`から全スクリプトが動的取得。不整合防止
15. **OSSとしての完成度**: MIT、CONTRIBUTING.md、SECURITY.md、CODEOWNERS、pull_request_template

### 弱み・リスク（上位15件、影響度付き）

| # | 項目 | 影響度 | 説明 |
|---|---|---|---|
| 1 | 認証fail-open | **重大** | デフォルトでトークンなし。LAN公開+トークン忘れで全API・セッション起動が無認証 |
| 2 | Codex YOLOモード自動付与 | **重大** | WebUIからCodexを起動すると必ず全権限モード。認証突破時のblast radius最大化 |
| 3 | symlinkルート検証バイパス | **重大** | `isInsideRoot`がrealpath解決しない。`~/projects/link → /etc`で任意ディレクトリ起動可能 |
| 4 | E2EテストがCIでskip | **高** | CLI不在のCIランナーでBats E2Eが常にskip。v0.3.0の起動不能回帰を検知できなかった |
| 5 | CSP `unsafe-inline` | **高** | XSS発生時の緩和効果なし。インラインoninputハンドラが根本原因 |
| 6 | localStorage平文トークン保存 | **高** | XSSまたは端末マルウェアでトークン窃取可能 |
| 7 | 関数の巨大化 | **中** | `handleUpgrade` 265行、`createApp` 618行。保守性・テスト容易性低下 |
